# Worldfolk: Claude contributor entry point

Before editing, read and follow [AGENTS.md](AGENTS.md). It is the shared repository instruction source for coding agents; avoid creating a second conflicting policy here.

## Recover project context

- [Project context and established decisions](docs/project-context.md) — the curated handoff from prior work, current focus and unresolved limits.
- [README](README.md) and [architecture](docs/architecture.md) — product, stack and code boundaries.
- [Roadmap](docs/roadmap.md), [place inventory](docs/realism/coverage-work-items.csv) and [implementation log](docs/realism/implementation-progress.md) — actual task status and evidence.
- [Local setup](docs/development.md), [testing](docs/contributing/testing.md) and [security policy](SECURITY.md) — safe commands and acceptance boundaries.

Private conversations are not part of the repository. Use recorded decisions and the current user's task; do not invent missing conversation history. Inspect the relevant source/tests before treating a dated note as current behavior.

## Working reminders

Preserve unrelated work and saved player state. Keep changes bounded; rebuild generated assets from their sources. Use real references for Accra locations and record estimates honestly. Protect server authority, resource disposal, collision/access and performance budgets together.

Run checks appropriate to the change and disclose existing failures. Do not start production login/deployment flows for local verification. Git operations, deployment, visibility changes and history rewrites require authorization for the current task. After the October 2026 history cleanup, use a fresh canonical clone and do not reintroduce old refs.

At handoff, summarize changes, commands/results, unresolved gaps and the next task. Maintain public project context without copying credentials, private chat or account details into these files.
